# luci-app-jxgm-drcom 设计方案

> 版本：v0.2（骨架阶段）；目标：Kwrt 25.12-SNAPSHOT / OpenWrt 25.12（apk + LuCI JS）；认证方式：curl。
> 说明：认证逻辑已按原 `drcom_web_login.sh` 重构并接入，本文档描述当前实现。

---

## 1. 目标与非目标

**目标**

- 在 LuCI「服务 → DrCOM」里完成：开关、账号配置、服务启停、运行状态、日志查看。
- 配置与登录脚本解耦：脚本只认 `/etc/config/drcom`，换学校/换脚本不动 UI。
- 纯脚本 + 前端包，`PKGARCH=all`，不编译二进制，能装在任何架构上。
- 掉线可恢复：procd 托管 + 脚本自身心跳 + 失败重试。

**非目标（v0.1 不做）**

- 不做多账号 / 多 WAN 多实例（预留 `TypedSection` 可扩展）。
- 不做门户网页抓包、不内置任何学校的 URL 规则。
- 不碰网络配置（静态 IP / MAC 克隆由用户在网络设置里配）。

## 2. 认证逻辑（已实现）

### 2.1 学校环境

- 江西工业贸易职业技术学院，DrCOM **eportal 网页认证**（不是 802.1X）。
- 门户：`http://10.100.100.30:801/eportal/portal/login`，JSONP 回调 `dr1003`。
- 账号拼接：`<前缀>,<学号>`，前缀由设备类型决定（电脑 `,0,`、手机 `,1,`），运营商非空时再拼 `@<运营商>`；学号固定 **`T` 开头 + 数字**（如 `T202XXXXXXX`）。
- 在线判定：请求 `http://connect.rom.miui.com/generate_204` 返回 `204` 即在线。
- 原脚本用 cron 定时跑；本包改为 **procd 常驻循环**，行为等价但可显示状态、可被 LuCI 启停。

### 2.2 脚本契约

```sh
/usr/share/drcom/drcom.sh run          # 常驻：检测 → 掉线则登录 → 间隔再检测
/usr/share/drcom/drcom.sh once         # 检测，离线才登录
/usr/share/drcom/drcom.sh login        # 跳过 204，直接发一次门户登录请求
/usr/share/drcom/drcom.sh check        # 在线 exit 0，离线 exit 1
/usr/share/drcom/drcom.sh probe <url>  # 打印 URL 的 HTTP 状态码（000=不可达）
/usr/share/drcom/drcom.sh ip           # 打印上行 IPv4 地址
/usr/share/drcom/drcom.sh mac          # 打印上行网卡的真实 MAC
/usr/share/drcom/drcom.sh set-mac <mac>  # 写入 network 配置并重载网络
```

约定：只从 UCI 读配置；前台运行、由 procd 守护；日志走 stdout（procd 转 syslog）+ `/var/log/drcom.log`；
密码永不进日志；状态写 `/var/run/drcom.state`。

### 2.3 相对原脚本的改进

| 原脚本 | 现在 | 原因 |
| --- | --- | --- |
| cron 定时执行 | procd 常驻循环 + respawn | 崩溃自恢复，能显示运行状态 |
| 无 WAN IP 直接 `exit 0` | 记录状态并等待重试 | 开机早期不会“静默失败” |
| 账号密码直接拼进 URL | `curl -G --data-urlencode` | 密码含 `& + =`、空格、中文也不会坏 |
| 只 `logger` 打一行 | 分级日志 + 文件 + 轮转 | 页面能看，排障有据 |
| 无成功判定 | 解析 `result`/`msg`，登录后再复检 204 | 区分“认证成功”和“实际能上网” |
| 无状态 | `/var/run/drcom.state` | 页面显示上次登录时间与结果 |
| `wlan_user_mac` 固定 0 | 可选真实 MAC | 个别校区需要 MAC 绑定 |

## 4. UCI 配置模型

`/etc/config/drcom`，单节 `config drcom 'main'`：

| 选项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `enabled` | bool | `0` | 开机自启；`boot()` 检查它，手动 start/restart 不检查 |
| `username` | string | 空 | 学号，**T 开头**，如 `T202XXXXXXX` |
| `password` | string | 空 | 密码（`uci` 明文存，权限 600） |
| `operator` | string | 空 | 运营商后缀：`unicom` / `cmcc` / `telecom`，可自定义；留空则不拼 `@后缀` |
| `iface` | string | `wan` | 上行网卡（设备名）；脚本同时接受逻辑接口名 |
| `portal_url` | string | 学校门户 | eportal 登录地址 |
| `check_url` | string | miui 204 | 连通性探测地址 |
| `interval` | int | `300` | 检测间隔（秒） |
| `retry_interval` | int | `15` | 单次失败后的重试间隔（秒） |
| `max_attempts` | int | `3` | 连续失败多少次后进入冷静期 |
| `cooldown` | int | `300` | 冷静期时长（秒） |
| `connect_timeout` | int | `5` | 请求超时（秒） |
| `use_real_mac` | bool | `0` | 勾选后发送上行接口真实 MAC，否则全 0 |
| `device_type` | enum | `pc` | `pc`=`,0,` + terminal_type 1；`mobile`=`,1,` + 2 |
| `v` | int | `7911` | 门户请求的 v 参数 |
| `v_random` | bool | `0` | 每次登录随机生成四位 v |
| `user_agent` | string | 空 | 留空用 curl 默认 UA，填写则覆盖 |
| `log_level` | enum | `info` | `error` / `warn` / `info` / `debug` |

账号由脚本拼成 `user_account=,0,${username}@${operator}`，编码交给 curl，不手工拼百分号。

```text
┌ JXGM DrCOM ────────────────────────────────────────────┐
│ 服务状态                                                │
│   服务        [运行中]                                  │
│   上次登录    2026-11-10 12:30:11                       │
│   最近结果    认证成功                                  │
│                                                        │
│ 服务控制                                                │
│   操作  [立即检测登录] [启动] [重启] [停止]              │
│                                                        │
│ 账号                                                    │
│   启用        [ ✓ ]                                     │
│   用户名      [2023xxxxT____]                           │
│   密码        [************]                            │
│   运营商      [中国联通 (unicom) ▾]   ← 可手动输入       │
│                                                        │
│ 门户                                                    │
│   登录地址    [http://10.100.100.30:801/...]            │
│   检测地址    [http://connect.rom.miui.com/...]         │
│   上行接口    [wan]                                     │
│   （真实 MAC 开关挪到“高级”页底部）                      │
│                                                        │
│ 高级                                                    │
│   检测间隔 / 重试间隔 / 连续失败 / 冷静期 / 超时 / 日志   │
├────────────────────────────────────────────────────────┤
│                          [Reset] [Save] [Save & Apply] │
└────────────────────────────────────────────────────────┘
```

控件全部使用 LuCI 现成的 form 元素，不手写页面结构：

- 状态三项 → `form.DummyValue`（`rawhtml=true`，只往里面塞 `label success/warning` 徽标）
- 四个动作 → `form.Button`（`inputstyle=primary/positive/negative`，`onclick` 里调脚本或 init 脚本）
- 配置项 → `tab` / `taboption` 分「基本 / 门户 / 高级」三页

交互：

- 「立即登录」调 `drcom.sh login`（**跳过 204 探测，直接请求门户**），不写 UCI；完成后刷新状态并弹通知。
- 「连通性检测地址」改完自动调 `drcom.sh probe`，结果实时显示在下方一行（不再弹窗打扰）。
- 门户页显示**上行网卡**真实 MAC（读 `/sys/class/net/<l3_device>/address`，失败回退 `ip link`），并提供「修改 MAC」：只改该设备的 `config device`（`drcom.sh set-mac`），写 `/etc/config/network` 后重载网络，带二次确认。
- 启停按钮调 `/etc/init.d/drcom`，与命令行等价。
- 保存走默认 footer（Save & Apply 带 30 秒回滚）；配置变更由 procd 的 `file` 参数触发实例重启。
- 状态 5 秒轮询：进程状态来自 `ubus service list`，时间/结果来自 `/var/run/drcom.state`。

### 6.2 日志页 `admin/services/drcom/log`

- `<pre>` 展示 `/var/log/drcom.log` 尾部 200 行，`poll.add` 5 秒刷新。
- 底部按钮：**停止刷新 / 继续刷新**（`poll.remove` / `poll.add`）、**清除日志**（`fs.write`，需 `write.file` 授权）。
- 页面切到后台时自动停轮询、切回来恢复（Page Visibility API）；用户手动暂停时优先级更高。
- 日志缺失时显示「暂无日志。」，不报错。

## 7. 状态模型

`/var/run/drcom.state`（tmpfs，重启即清）：

```text
status=online
updated=1762750000
last_login=1762749000
message=认证成功
```

`status` 取值：

| 值 | 含义 |
| --- | --- |
| `online` | 204 探测通过 |
| `offline` | 探测失败，正在登录 |
| `auth-failed` | 登录被拒或请求失败 |
| `no-wan` | 接口还没有 IPv4 |

页面把 `last_login` 显示成“上次登录”，`message` 显示成“最近结果”；进程是否在跑看 `service list`。

## 8. 日志策略

- 脚本 stdout/stderr 由 procd 收到 syslog（`logread -e drcom` 可查）。
- 同时追加到 `/var/log/drcom.log`（tmpfs，重启即清），脚本内部做了大小上限（建议 256 KB 截断）。
- UI 只读文件，不去 `logread` 反复扫（省 CPU；`logread` 作为二级信息源保留在 ACL 里）。
- 日志格式建议：`2026-11-09 23:50:12 [info] login ok, ip=10.x.x.x`。

---

## 9. 安全

- `/etc/config/drcom` 权限 `600`，`uci-defaults` 里 `chmod 600`。
- 日志永不打印密码；`ucode`/`sh` 两边都要过一遍。
- ACL 最小化：只开本应用需要的 `uci:drcom`、`service:list`、三个文件权限。
- 不新增 root 可执行入口：`drcom.sh` 只接受 `run|once|check` 三个参数，其他直接退出。

## 10. 构建 / 安装 / 升级

```sh
# Kwrt 25.12 源码树内（该版本仍是 opkg，产物为 .ipk）
./scripts/feeds update -a && ./scripts/feeds install -a
cp -r luci-app-jxgm-drcom package/
make package/luci-app-jxgm-drcom/compile V=s
# 产物：bin/packages/<arch>/luci/luci-app-jxgm-drcom_0.1.0-r1_all.ipk

# 设备上
opkg install /tmp/luci-app-jxgm-drcom_0.1.0-r1_all.ipk
/etc/init.d/drcom enable
/etc/init.d/drcom start
```

> 同一份 Makefile 在启用 `CONFIG_USE_APK` 的树（官方 25.12 及以后）上会自动产出 `.apk`，源码不用改。
> `/etc/config/drcom` 已写入 `Package/<pkg>/conffiles`，升级不会覆盖用户填的账号密码。
