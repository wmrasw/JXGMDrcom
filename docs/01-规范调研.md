# OpenWrt / Kwrt LuCI 软件包规范调研

> 目标：给 `luci-app-jxgm-drcom`（JXGM DrCOM 校园网自动登录）定下一套可落地的编写、UI、打包规范。
> 调研时间：2026-11；对象：**OpenWrt 25.12 线**（目标设备 Kwrt 25.12-SNAPSHOT，内核 6.12，apk + LuCI JS）。

---

## 0. 结论速览（先看这 8 条）

1. **LuCI 现在只有一种正确写法**：JS 视图 + `menu.d` + `acl.d` + `rpcd`，Lua CBI（`luasrc/controller/*.lua`）属于 legacy，只适用于 ≤19.07 或装了 `luci-compat` 的老环境。
2. **一个 LuCI 应用 = 一个 feed 包目录** `luci-app-<name>/`，固定 4 个位置：`Makefile`、`htdocs/luci-static/resources/view/<name>/`、`root/usr/share/luci/menu.d/`、`root/usr/share/rpcd/acl.d/`。
3. **`Makefile` 只写元数据**（`LUCI_TITLE` / `LUCI_DEPENDS` / `PKG_LICENSE` …），然后 `include luci.mk`；`luci.mk` 自动处理编译、安装、压缩、i18n 子包、postinst 清缓存。
4. **权限走 ACL**，不是 root 裸奔：`uci`、`ubus`、`file`（`read` / `write` / `exec`）三类都要在 `acl.d` 里显式授权，否则页面报 “Access denied”。
5. **UI 没有单独的“设计规范”文档**；事实标准 = `luci-app-example` + `luci.js/form.js` API + 主题 CSS 类（`cbi-*`、`label.success` 等）。照抄官方示例的结构和类名即可跨主题（bootstrap / argon）一致。
6. **页面生命周期固定**：`load()` 取数据 → `render()` 出 DOM → 页脚 `Save` / `Save & Apply` / `Reset` 由 `view` 基类提供，重写 `handle*` 或置 `null` 关闭。
7. **服务用 procd**：`/etc/init.d/<svc>` 里 `USE_PROCD=1` + `procd_open_instance` / `procd_set_param respawn`，不要自己写 while 循环 + nohup。
8. **打包产物**：24.10 及以前是 `opkg` → `.ipk`；**官方 25.12 起换成 `apk`（apk-tools v3）** → `.apk`。但第三方定制不一定跟进——**Kwrt 这个 25.12 版本仍然用 opkg/ipk**。产物后缀由构建树的 `CONFIG_USE_APK` 决定，源码不用改。

## 1. 软件包编写规范

### 1.1 包目录与 Makefile 必备字段

官方包规范的核心在 `include/package.mk`：`BuildPackage` 会强制检查 `TITLE` / `CATEGORY` / `SECTION` / `VERSION` 四个字段，缺一个直接 `error`。
参考：[include/package.mk](https://github.com/openwrt/openwrt/blob/master/include/package.mk)、[packages/CONTRIBUTING.md](https://github.com/openwrt/packages/blob/master/CONTRIBUTING.md)。

```make
include $(TOPDIR)/rules.mk

PKG_NAME:=luci-app-jxgm-drcom
PKG_VERSION:=0.1.0
PKG_RELEASE:=1

PKG_LICENSE:=Apache-2.0
PKG_MAINTAINER:=Your Name <you@example.com>

include $(TOPDIR)/feeds/luci/luci.mk

# $(eval $(call BuildPackage,luci-app-jxgm-drcom)) 由 luci.mk 自动完成
```

要点：

| 字段 | 规范 |
| --- | --- |
| `PKG_LICENSE` | 用 SPDX 标识（`Apache-2.0`、`MIT`…），不要写 `Apache 2.0` 这种非标准写法 |
| `PKG_MAINTAINER` | 真实姓名 + 邮箱；空着能过，但 review 会慢 |
| `PKG_RELEASE` | 初值 1；**改代码/脚本/编译选项就 +1**，只改 md5、注释、镜像地址不用 |
| `PKG_VERSION` | 独立仓库没有 `PKG_SOURCE` 时必须自己写，否则 `luci.mk` 的 `findrev` 会给出 `0` |
| `Package/<name>/install` | 用 `$(1)` 作为 staging 根，`$(INSTALL_DIR)` / `$(INSTALL_BIN)` / `$(CP)`，不要用绝对路径 |

### 1.2 `luci.mk` 替我们做的事

读 [luci.mk](https://github.com/openwrt/luci/blob/master/luci.mk) 可以确认这些“白送”的行为：

- `Build/Prepare` 自动拷贝 `htdocs/` `root/` `luasrc/` `ucode/` `src/`（存在才拷）。
- `Package/<pkg>/install` 自动把 `htdocs/` 装到 `/www`、`root/` 装到 `/`、`luasrc/` 装到 `/usr/lib/lua/luci`、`ucode/` 装到 `/usr/share/ucode/luci`。
- `postinst` 自动 `rm -rf /tmp/luci-indexcache.* /tmp/luci-modulecache/` 并 `reload rpcd` —— 所以改菜单/ACL 后**重装包**即可生效，不用手动清缓存。
- 自动做 JS/CSS 压缩（`CONFIG_LUCI_JSMIN`、`CONFIG_LUCI_CSSTIDY`）、ucode 模板预编译。
- `po/<lang>/*.po` 会自动生成 `luci-i18n-<basename>-<lang>` 子包，并把语言注册进 `luci.languages`。
- `LUCI_PKGARCH:=all` → 纯脚本/前端包，不跟 CPU 架构绑定（我们这种包必须设）。

### 1.3 包名与目录约定

- 目录名 = 包名 = `luci-app-<name>`，`<name>` 不带前缀（`drcom`）。
- 视图路径：`htdocs/luci-static/resources/view/<name>/<page>.js`，菜单里写 `"path": "<name>/<page>"`。
- 共享模块放 `htdocs/luci-static/resources/<name>/`，视图里用 `'require <name>.status'` 引用。
- `/etc` 下的文件**不会**被自动当成 conffile：必须在 Makefile 里显式写 `define Package/<pkg>/conffiles`，否则升级会覆盖用户配置（apk/opkg 都一样）。
- 服务脚本放 `root/etc/init.d/<svc>`，业务脚本放 `root/usr/share/<pkg>/` 或 `root/usr/bin/`。

### 1.4 Shell / JS 编码约定

- Shell：`#!/bin/sh` + POSIX，变量全部加引号；procd 服务脚本 `#!/bin/sh /etc/rc.common`。
- JS：LuCI 风格是 **Tab 缩进、单引号、`'use strict'` 第一行、`'require x'` 声明块**，不引入打包器，代码必须能被 24.10 的浏览器直接跑（不要用可选链 `?.`、`??` 之类太新的语法，老 Android WebView 会挂）。
- 所有用户可见字符串外包 `_()`，否则 i18n 子包抓不到。

## 2. LuCI UI 规范

### 2.1 应用目录结构（官方示例）

```
luci-app-example/
├── Makefile
├── README.md
├── htdocs/luci-static/resources/view/example/*.js
├── po/templates/example.pot
└── root/
    ├── etc/uci-defaults/80_example
    └── usr/
        ├── share/luci/menu.d/luci-app-example.json
        └── share/rpcd/{acl.d/luci-app-example.json, ucode/example.uc}
```

来源：[structure.md](https://github.com/openwrt/luci/blob/master/applications/luci-app-example/structure.md)。

### 2.2 菜单（menu.d）

父级菜单 `admin/services`（“服务”）由 `luci-base` 提供，第三方应用直接挂子节点：

```json
{
  "admin/services/drcom": {
    "title": "DrCOM",
    "order": 60,
    "action": { "type": "firstchild" },
    "depends": { "acl": [ "luci-app-jxgm-drcom" ] }
  },
  "admin/services/drcom/overview": {
    "title": "Settings",
    "order": 1,
    "action": { "type": "view", "path": "drcom/overview" }
  }
}
```

- 可用的 `action.type`：`view`、`firstchild`、`function`、`template`、`alias`、`cbi`（legacy）。
- `order` 是同级排序（10/20/30…），留空则按字母序。
- `depends.acl` 让没有权限的用户**看不到**该菜单；`depends.fs` 可以按文件是否存在决定显示。

### 2.3 ACL（acl.d）

ACL 决定这个应用的会话能调哪些 ubus / uci / 文件。**文件类权限里 `exec` 也写在 `read` 段**（官方 `luci-app-aria2` 就是这么写的）：

```json
{
  "luci-app-jxgm-drcom": {
    "description": "Grant UCI, service and file access to luci-app-jxgm-drcom",
    "read": {
      "ubus": { "service": [ "list" ] },
      "uci": [ "drcom" ],
      "file": {
        "/etc/init.d/drcom": [ "exec" ],
        "/sbin/logread": [ "exec" ],
        "/var/log/drcom.log": [ "read" ]
      }
    },
    "write": { "uci": [ "drcom" ] }
  }
}
```

经验规则：

| 前端动作 | 需要的 ACL |
| --- | --- |
| `uci.load/get/set` | `read.uci` / `write.uci` + 配置名 |
| `rpc.declare({object:'service', method:'list'})` | `read.ubus.service:["list"]` |
| `fs.exec('/etc/init.d/x')` | `read.file."/etc/init.d/x":["exec"]` |
| `fs.read('/var/log/x')` | `read.file."/var/log/x":["read"]` |
| 读取 `uci` 之外的文件（如 `/etc/drcom.conf`） | 对应 `read.file` 条目 |

漏配的典型症状：页面能开，但一点按钮就 `Access denied` / `Permission denied`。

### 2.4 视图生命周期

来源：[LuCI.view](https://openwrt.github.io/luci/jsapi/LuCI.view.html)。

```js
return view.extend({
	load: function() { /* 返回 Promise 或值，结果传给 render */ },
	render: function(data) { /* 必须返回 Node / DocumentFragment */ },
	handleSave: null,        // 置 null 可隐藏页脚按钮
	handleSaveApply: null,
	handleReset: null
});
```

- 页脚 `Save` / `Save & Apply` / `Reset` 由基类自动渲染，`form.Map` 场景不用自己写保存逻辑。
- `handleSaveApply` 默认 = 保存 + `ui.changes.apply()`（带 30 秒回滚确认弹窗），**这是 LuCI 的标准“应用配置”体验**，不要自己 `uci commit`。

### 2.5 表单与控件

标准写法（`form.Map` + 匿名 `TypedSection`，来自官方 example）：

```js
m = new form.Map('drcom', _('DrCOM Auto Login'), _('Campus network auto login.'));
s = m.section(form.TypedSection, 'settings', _('Account'));
s.anonymous = true;

o = s.option(form.Value, 'username', _('Username'));
o.datatype = 'string';
o.rmempty = false;

o = s.option(form.Value, 'password', _('Password'));
o.password = true;

o = s.option(form.Flag, 'enabled', _('Enable'));
o.default = '0';
o.rmempty = false;
```

常用属性：`datatype`（`uinteger` / `port` / `ipaddr` / `range(a,b)` / `hostname`）、`placeholder`、`password`、`rmempty`、`optional`、`depends('other','value')`（联动显隐）、`modalonly`（只在弹窗里出现）、`default`。
`form.TypedSection` / `NamedSection` / `GridSection` / `TableSection` 的选择：单实例配置用 `NamedSection` 或匿名 `TypedSection`；多条记录（账号列表、规则列表）用 `GridSection` + `addremove`。

### 2.6 状态、提示、轮询、按钮

这套是 LuCI 页面的“交互规范”，跨主题通用：

```js
// 状态徽标（主题里定义了 .label.success/.warning/.important/.notice）
E('span', { 'class': running ? 'label success' : 'label warning' }, _('Running'));

// 通知（type: info / warning / danger / success）
ui.addNotification(null, E('p', _('Service restarted.')), 'info');

// 轮询（秒），返回的 handle 可 .remove()
poll.add(function() { ... return Promise; }, 5);

// 执行命令
fs.exec('/etc/init.d/drcom', [ 'restart' ]).then(function(res) { res.code, res.stdout, res.stderr });

// 重绘容器
dom.content(node, newContent);
```

样式类一律用 LuCI 主题已有的：`cbi-section`、`cbi-value`、`cbi-value-title`、`cbi-value-field`、`cbi-page-actions`、`cbi-button cbi-button-apply|negative|positive`、`table`、`ifacebox`、`label`。
**不要写内联 style 做布局**（个别日志页 `<style>` 除外，官方 aria2 也这么干），否则暗色模式和移动端会坏。

### 2.7 i18n

- 源码用英文 `_('...')`，翻译放 `po/<lang>/<name>.po`（`zh_Hans` 对应 `luci-i18n-<basename>-zh-cn`）。
- **例外**：本项目面向校内中文用户，msgid 直接写中文（仍保留 `_()`），这样手工部署也能立即中文，不依赖 i18n 子包与 `.lmo` 编译；以后要英文再补反方向 po。
- `luci.mk` 用 `po2lmo` 编译 `.po`，缺 `msgstr` 会回退英文，不会崩。
- 中文用户占比高的话，`zh_Hans` 是必须项，但仍建议保留英文 msgid。

## 3. 打包与发布规范

### 3.1 三种使用方式

| 方式 | 做法 | 适用 |
| --- | --- | --- |
| 塞进固件源码 | 放 `package/luci-app-jxgm-drcom/`，`make menuconfig` 勾选，`make package/luci-app-jxgm-drcom/compile V=s` | 自己编译固件 |
| 作为 feed | `echo 'src-link drcom /path/to/feed' >> feeds.conf.default` → `./scripts/feeds update/install drcom` | 多包维护 |
| 独立 SDK | 解压 SDK，把包放 `package/`，`make package/luci-app-jxgm-drcom/compile V=s`，产物在 `bin/packages/<arch>/luci/` | 只出安装包 |

包必须先找到 luci feed 才能编译（`luci.mk` 在 feed 根目录）。本包的 Makefile 用
`$(TOPDIR)/feeds/*/luci.mk` 搜索，找不到时给出明确报错，而不是一句 `No rule to make target`。

### 3.2 目标环境：Kwrt 25.12-SNAPSHOT（opkg）

- **上游 25.12 用 apk，但 Kwrt 这个版本仍用 opkg/ipk**。产物后缀由构建树的 `CONFIG_USE_APK`
  决定，源码不用改：`CONFIG_USE_APK` 未开 → `luci-app-jxgm-drcom_0.1.0-r1_all.ipk`，
  开了 → `luci-app-jxgm-drcom-0.1.0-r1.apk`（注意分隔符也不同）。
- 安装命令：`opkg install xxx.ipk`；校验用 `opkg list-installed | grep jxgm`。
- **LuCI 是 25.12 分支**（`openwrt/luci` 的 `openwrt-25.12`）：`luci-app-example` 的 Makefile / 目录结构与 master 一致，
  菜单、ACL、视图 API 都没变；新增的只是示例里的 `root/etc/luci.example.yaml`（可选特性，不必跟）。
- **Kwrt 是第三方定制固件**（Kiddin' 维护，内核 6.12），基于 25.12 snapshot 构建。
  它的 luci feed 目录名不一定是 `luci`，所以 Makefile 用通配搜索 `feeds/*/luci.mk`，避免写死路径。
- **snapshot 的 ABI 风险**：源码包（`PKGARCH:=all`）不受 CPU 架构影响，但 `+luci-base` 依赖会按包名解析；
  用与设备同源的 SDK/源码树编译最稳，跨 snapshot 直接装偶尔会遇到 luci-base 版本差异。
- **主题**：Kwrt 通常用 argon，部分设备用 bootstrap；样式类只用两边都实现的 `cbi-*` / `label.success|warning`。

### 3.3 发布约定

- 打 tag 时 `PKG_RELEASE:=1`，改脚本/页面后 `+1`。
- 提交信息按官方风格：`luci-app-jxgm-drcom: 描述`，带 `Signed-off-by`（若往官方 feed 提）。
- 官方仓库对 AI 生成内容有明确政策（`packages/CONTRIBUTING.md` 的 AI policy）：提交 PR 必须披露 LLM 使用；我们自建仓库不受限，但代码要能自己讲清楚。

## 4. 可参考的 DrCOM 项目

| 项目 | 形态 | 可借鉴点 |
| --- | --- | --- |
| [mchome/dogcom](https://github.com/mchome/dogcom) | C 实现 802.1X DrCOM 客户端 | 协议参数（`AUTH_VERSION`、`KEEP_ALIVE_VERSION`、`mac` 0x 格式） |
| [mchome/openwrt-dogcom](https://github.com/mchome/openwrt-dogcom) | 上述客户端的 OpenWrt 包 | 交叉编译 + `files/` 布局；注意它**不带 init 脚本** |
| [sweetcornna/jlu_drcom](https://github.com/sweetcornna/jlu_drcom) | 完整 OpenWrt 包 + LuCI 页面 | 配置项设计、日志/诊断页、SDK 打包脚本；其 LuCI 仍是 Lua 控制器，UI 部分不要照抄 |
| 各校 WEB 门户脚本 | `curl` 登录 + 心跳 | 适合“有可用 sh”的场景：账号/密码/门户地址/心跳间隔 |

关键区分：**WEB 门户认证**（HTTP 表单，sh + curl 就能做）与 **802.1X 客户端认证**（UDP 61440，需要 dogcom 这类二进制）。我们这版按“用户提供可用 sh”来做，默认是前者；如果 sh 里其实调用了 dogcom，则要额外加架构相关的二进制包。

## 5. 规范 → 本项目的落点

| 规范条目 | 本项目实现 |
| --- | --- |
| 包结构 | `luci-app-jxgm-drcom/`，Makefile + htdocs + root + po |
| 元数据 | `LUCI_TITLE`、`LUCI_DEPENDS:=+luci-base +curl +jsonfilter`、`LUCI_PKGARCH:=all` |
| 配置 | `/etc/config/drcom`（conffile），单一 `config drcom 'main'` |
| 服务 | `/etc/init.d/drcom`（procd）+ `/usr/share/drcom/drcom.sh`（run / once / check） |
| 菜单 | `admin/services/drcom` → 设置 / 日志 |
| 权限 | `acl.d` 最小授权（uci drcom、service list、init/脚本 exec、日志与状态 read） |
| UI | `form.Map` 表单 + 状态徽标 + 启停按钮 + `poll.add` 日志页 + 页脚 Save & Apply |
| i18n | 中文 msgid + `_()` 包裹（预留英文 po） |
| 打包 | `feeds/*/luci.mk`（自动搜索），SDK 出 ipk（Kwrt） |
